How I got here

I started in 2020 as a Linux administrator in Kochi, patching servers, writing cron jobs and shell scripts so nobody had to create user accounts by hand. That habit of scripting away the boring parts is what pulled me into DevOps.

From there I moved into cloud work. At Taal Tech I provisioned environments across AWS, Azure and GCP and wrote my first real Terraform. At Amistad I was on the support side, handling L1/L2 incidents, and learned how much a good alert or a clean rollback is worth at 2 a.m.

After my master’s in Management Information Systems I joined State Farm, where I work on the platform behind their AI and ML work: pipelines, Kubernetes clusters, GPU capacity, secrets and monitoring. It’s the most interesting mix I’ve worked on, because a model is only useful once it’s reliably in production.

What I care about

  • Do it by hand once, then automate it. If I’m clicking through a console a second time, that’s a script or a module waiting to happen.
  • Rollback should be cheaper than debugging. I’d rather ship small changes behind a canary and undo them in minutes than chase a bad release for hours.
  • If it isn’t monitored, it isn’t done. Dashboards and alerts are part of the feature, not a follow-up ticket.
  • Security belongs in the pipeline. A failed scan should stop a build, not show up in a report next quarter.

Selected work

The problem, what I did about it, and what changed. Most of this is from my work with State Farm’s ML platform.

40% shorter release cycles

The problem

Teams were shipping ML services through pipelines spread across different tools, and getting a change from merge to production took longer than it should.

What I did

Built and tuned CI/CD on GitHub Actions, Jenkins and Buildkite, with Terraform and CloudFormation handling the infrastructure underneath, so every environment came from code instead of tickets.

What changed

Release cycles got 40% shorter, and the infrastructure behind them held 99.9% uptime.

GitHub Actions, Jenkins, Buildkite, Terraform, CloudFormation

95% fewer release interruptions

The problem

Every release was a moment of risk. If something went wrong, users felt it before anyone could react.

What I did

Moved services on EKS and GKE to blue-green and canary rollouts managed through ArgoCD and FluxCD, with Helm charts and autoscaling for the high-traffic apps. Rollbacks became automatic instead of a manual scramble.

What changed

Interruptions during releases dropped 95%, and recovering from a bad deploy went from hours to minutes. The playground above is a small version of this setup.

Kubernetes (EKS, GKE), Helm, ArgoCD, FluxCD

30% faster training, 15% lower cost

The problem

Deep learning workloads need GPUs, and GPUs are expensive to leave idle and painful to wait for.

What I did

Set up GPU and TPU clusters with Terraform, automated monitoring and scaling around the training jobs, and wired SageMaker, Bedrock and Hugging Face into the deploy pipeline. I also worked with data scientists and ML engineers to get LLM-based apps into production.

What changed

Training and inference ran up to 30% faster while GPU spend went down 15%.

GPU and TPU clusters, Terraform, SageMaker, Bedrock, Hugging Face

25% less downtime

The problem

Issues were getting noticed after users reported them, not before.

What I did

Brought Prometheus, Grafana, CloudWatch and the ELK stack together with dashboards and predictive alerts. I also handle incident response and write up root cause reviews so the same problem doesn’t come back.

What changed

Downtime went down 25%, and anomalies started showing up on a dashboard before they showed up in a support queue.

Prometheus, Grafana, CloudWatch, ELK

35% fewer vulnerabilities

The problem

Security checks happened late, so problems were found after code was already on its way out.

What I did

Put Snyk, Trivy and SonarQube into the CI/CD workflows as gates, and moved secrets into Vault, AWS Secrets Manager and GCP Secret Manager.

What changed

Vulnerabilities dropped 35% and code compliance improved, because bad builds now fail early instead of shipping.

Snyk, Trivy, SonarQube, Vault, AWS and GCP Secret Manager
