The situation

The teams I support build and serve machine learning models across AWS and GCP. Code moved through pipelines on more than one CI system, and environments didn’t always come from the same source of truth.

The result was predictable: changes waited longer than they needed to, and every release carried a bit of extra uncertainty because the path to production wasn’t the same every time.

What I built

  • Developed and tuned CI/CD pipelines on GitHub Actions, Jenkins and Buildkite, so each service has a clear, repeatable path from commit to production.
  • Provisioned and secured the infrastructure behind those pipelines with Terraform and CloudFormation, so environments are created from code and reviewed like code.
  • Brought ML lifecycle tools, SageMaker, Bedrock and Hugging Face, into the same pipelines so model deployments follow the same rules as application code.

How it flows

  1. Pull request
  2. Build and test
  3. Scan
  4. Package
  5. Deploy with GitOps
  6. Monitor

Decisions I made and why

Meet teams where they are

Moving every team to one CI tool overnight would have stalled delivery. I focused on making each path consistent and fast first, using the tool the team already ran.

Infrastructure is reviewed like code

Terraform and CloudFormation changes go through pull requests. That turns environment changes into something people can read, discuss and roll back.

Models ship like software

A model deploy gets the same build, scan and rollout steps as a service. Fewer special cases means fewer surprises.

What changed

Release cycles got 40% shorter, and the infrastructure provisioned this way held 99.9% uptime.

What I’d do next

Measure lead time and change failure rate per team as standing metrics, so improvements show up on a dashboard instead of in anecdotes.
